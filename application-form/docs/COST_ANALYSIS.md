## 月額コスト見積もり（現在）

### Cloud Run (メインプラットフォーム)
- **構成**: CPU 1, メモリ 0.5GiB, min-instances=0（オンデマンド起動）
- **実際の見積もり**: min-instances=0のため、リクエスト時のみ課金
  - **リクエスト数**: 推定10,000-100,000リクエスト/月
  - **リクエスト料金**: 最初の200万リクエスト/月は無料 = **$0/月**
  - **CPU時間**: 推定10-50時間/月 × $0.0864/時間 = **$0.86-4.32/月**
  - **メモリ時間**: 推定10-50時間/月 × $0.009/時間 = **$0.09-0.45/月**
  - **合計: $1-5 USD/月**

### Cloud Run (面接システム)
- **構成**: CPU 1, メモリ 1GiB, min-instances=0（オンデマンド起動）
- **実際の見積もり**: min-instances=0のため、リクエスト時のみ課金
  - **リクエスト数**: 推定1,000-10,000リクエスト/月（面接10-100回）
  - **リクエスト料金**: 最初の200万リクエスト/月は無料 = **$0/月**
  - **CPU時間**: 推定5-20時間/月 × $0.0864/時間 = **$0.43-1.73/月**
  - **メモリ時間**: 推定5-20時間/月 × $0.009/時間 = **$0.045-0.18/月**
  - **合計: $0.50-2 USD/月**

### Cloud SQL
- **固定費**: **$7.50/月**（db-f1-micro）
- **バックアップ**: 含まれている（自動バックアップ）

### Cloud Storage
- **現在**: 0.006GB × $0.020/GB/月 = **$0.00012/月**（ほぼ無料）
- **1,000面接/月**: 200MB (0.2GB) × $0.020/GB/月 = **$0.004/月**
- **10,000面接/月**: 2GB × $0.020/GB/月 = **$0.04/月**
- **100,000面接/月**: 20GB × $0.020/GB/月 = **$0.40/月**

### Cloud Build（デプロイ時のみ）
- **ビルド時間**: 約3-5分/回 × $0.003/分 = **$0.009-0.015/回**
- **月間デプロイ**: 10-20回 = **$0.09-0.30/月**

### ネットワーク（データ転送）
- **Cloud Run → インターネット**: 最初の10GB/月は無料
- **Cloud Storage → インターネット**: 最初の1GB/月は無料
- **推定**: **$0-2/月**（通常使用量では無料枠内）

### 合計（現在）
- **月額: $9-17 USD**（約1,350-2,550円）
  - Cloud SQL: $7.50（固定費、コストの大部分）
  - Cloud Run (メイン): $1-5（使用量に応じて）
  - Cloud Run (面接): $0.50-2（使用量に応じて）
  - Cloud Storage: $0-0.01（ほぼ無料）
  - その他 (Build, Network): $0.50-2

### 詳細なコスト内訳

#### Cloud Runのコスト増加
- **リクエスト数**: 最初の200万リクエスト/月は無料
- **CPU時間**: リクエスト数に比例（面接1回 = 約5-10リクエスト）
- **メモリ**: CPU時間に比例

#### Cloud Storageのコスト増加
- **録画ファイル**: 約20KB/録画 × 10問 = 約200KB/面接
- **100面接/月**: 20MB = **$0.0004/月**
- **1,000面接/月**: 200MB = **$0.004/月**
- **10,000面接/月**: 2GB = **$0.04/月**
- **100,000面接/月**: 20GB = **$0.40/月**

## コスト最適化の推奨事項

### 1. ✅ 既に実装済みの最適化
- **min-instances=0**: 使用時のみ課金（コールドスタート許容）
- **古い録画の自動削除**: ストレージコストを抑制
- **最小構成の使用**: db-f1-micro、最小メモリ構成

### 2. 追加で検討できる最適化

#### Cloud Storageライフサイクル管理
```bash
# 90日以上経過した録画を自動削除
cat > lifecycle.json << EOF
{
  "lifecycle": {
    "rule": [
      {
        "action": {"type": "Delete"},
        "condition": {
          "age": 90
        }
      }
    ]
  }
}
EOF
gsutil lifecycle set lifecycle.json gs://justjoin-platform-match-job-documents/interview-recordings
```

#### Cloud Runの自動スケーリング設定
- 現在: max-instances=10（面接システム）
- 推奨: 必要に応じて調整（ただし、急増時に対応できるように）

#### Cloud SQLの最適化
- 現在: db-f1-micro（最小構成）で十分
- データが増加した場合のみアップグレードを検討

### 3. 監視とアラート設定

1. **Cloud RunのCPU/メモリ使用時間**: リクエスト数に比例（ただし、最初の200万リクエストは無料）
2. **Cloud Storageの容量**: 録画ファイル数に比例（ただし、自動削除で抑制）
3. **Cloud SQL**: 固定費（データが増加しても10GBまでは同じコスト）

### 結論
- **現在の構成は非常にコスト効率が良い**（最小構成で最適化済み）

- **登録者が増えても、コストは緩やかに増加**（リニアではなく）
- **無料枠（200万リクエスト/月）を活用できている**
